# spec.md — AI Video Factory 素材缺口 AI 生成补位规格

> **唯一真实来源（Single Source of Truth）。** 本文档定义系统"做什么"，不涉及"怎么做"。所有 plan、tasks、代码实现以此为准。
>
> 关联：`../constitution.md` | 基础架构：`../video-factory-arch/spec.md` | 前一阶段优化：`../video-factory-optimize/spec.md`

## 1. Problem Statement

现有管线在"分镜素材匹配"环节存在三类无法自洽的缺口：

**素材库覆盖不足。** 当前素材库依赖人工收集（T1.6 至今未启动），实测素材命中率仅 25%（2/8 分镜）。`video-factory-optimize` 规格已规划接入 Pexels/Pixabay 外部免费素材源，但仍受限于这些库的内容覆盖——抽象概念、特定产品形态、品牌色配图等场景无现成素材。

**特殊视觉素材无法外购。** 视频封面图、转场插画、概念可视化（如"数字化转型""内卷"等抽象主题）、透明 PNG 叠加层等，本质上是"定制化图形"，外部素材库命中率接近零，而现有人工设计成本高、响应慢。

**缺口阻断管线。** 当前素材缺失分镜标记为 `no_match: true` 后只能使用渐变背景兜底，画面单调，拉低整体观感与完播率。

**目标：** 在素材检索链路末端加入"AI 文生图补位"能力，当本地素材库与外部素材源均未命中时，按需生成配图、封面、背景、透明 PNG、转场素材，让任意分镜都能获得可用画面。本规格**仅覆盖静态图像**，不涉及视频生成。

## 2. Success Metrics

| 指标 | 目标值 | 测量方式 |
|------|--------|----------|
| 素材综合命中率 | ≥ 90%（本地 + 外部 + AI 生成合并） | 分镜审阅"通过"率统计 |
| AI 生成素材审阅通过率 | ≥ 70% | 分镜审阅 / 成片审阅中 AI 素材的"通过 / (通过+打回)" |
| 单张生成耗时 | ≤ 30 秒 | 生成调用时间戳差值 |
| 单张生成成本 | ≤ ¥0.5 | API 平台账单 |
| 新增月成本增量 | ≤ ¥30（按日均 3 条视频 × 每条约 3 张 AI 素材估算） | API 平台账单 |
| 管线阻断率 | 不高于现状（AI 生成失败必须有兜底，不允许卡在补位环节） | 端到端管线成功率对比 |
| 横竖屏双适配 | 生成素材可正确匹配 1920×1080 与 1080×1920 两种输出 | 渲染成片 ffprobe 验证 + 人工抽看 |

## 3. User Stories

| # | 角色 | 场景 | 期望结果 |
|---|------|------|----------|
| US-1 | 内容创作者 | 我的分镜在本地库和外部素材源都找不到合适画面 | 系统自动生成一张符合分镜文案与画面建议的配图，无需我手动设计 |
| US-2 | 内容创作者 | 我想给视频配一张吸引人的封面 | 系统根据标题与钩子文案自动生成封面候选，发布元数据审阅时一并确认 |
| US-3 | 内容创作者 | AI 生成的某张图我不喜欢 | 在分镜审阅或成片审阅时标记"重新生成"，系统基于原 prompt 与我的反馈再生成一张 |
| US-4 | 内容创作者 | 我需要在画面角落加一个图标 / LOGO / 装饰元素 | 系统生成透明背景 PNG，可直接叠加到视频上 |
| US-5 | 运营者 | 我想区分哪些素材是 AI 生成的 | 素材元数据中带有明确标记，可追溯、可统计、可一键清理 |
| US-6 | 内容创作者 | 同一条视频要发 YouTube 和抖音 | 同一分镜的 AI 素材能按目标平台分别生成横屏 / 竖屏版本，画面主体不被裁切 |

## 4. Acceptance Criteria

### AC-1: 触发时机与降级链

- AI 生成仅在以下两条路径**全部 miss** 后触发：① 本地素材库检索；② 外部免费素材源（`video-factory-optimize` 规格 AC-6 引入）。
- 触发粒度为"分镜"级别，不是"整条视频"级别——允许同一条视频部分分镜用实拍素材、部分用 AI 生成。
- AI 生成失败时，按以下顺序降级：重新生成 1 次 → 切换备用图像风格 → 回退到现有渐变背景渲染。任何情况下**不允许阻断管线**。
- 默认不在以下场景触发 AI 生成：分镜文案明确指向"实拍""采访""街拍"等需要真实画面的场景（由分镜 `suggestion` 与 `required_tags` 字段判定）。

### AC-2: 生成类型与用途

必须支持以下四类素材生成，每类对应明确的管线消费位置：

| 类型 | 用途 | 消费位置 |
|------|------|----------|
| 分镜配图 | 替代缺失的视频画面 | 渲染管线的分镜层 |
| 封面图 | 视频封面 / 缩略图 | 发布元数据（审阅点 4） |
| 背景图 | 替代默认渐变背景 | 渲染管线的背景层 |
| 透明 PNG | 图标、装饰、强调元素 | 渲染管线的叠加层 |

同一分镜允许同时生成多种类型（例如"配图 + 透明 PNG 角标"）。

### AC-3: 尺寸与平台适配

- 横屏模板（16:9）生成素材分辨率不低于 1920×1080。
- 竖屏模板（9:16）生成素材分辨率不低于 1080×1920。
- 同一分镜如需双平台分发，必须分别按横竖两个尺寸生成，**禁止简单裁切**——画面主体构图需按方向重新规划。
- 透明 PNG 输出带 Alpha 通道，分辨率不低于 1024×1024。

### AC-4: 内容约束与品牌一致性

- 生成内容必须遵守目标平台内容规范（无血腥、无政治敏感、无版权风险图案如知名 IP 形象、商标、名人肖像）。
- 同一条视频内多张 AI 素材的视觉风格需保持一致（色调、画风、笔触）。
- 用户可在管线入口提供"风格描述"（如"扁平插画风""3D 渲染风""极简线条"），全片沿用。
- 必须支持负向约束（negative prompt），默认排除"水印、文字、logo、二维码、人脸特写"。

### AC-5: 元数据与入库

- 所有 AI 生成素材必须落盘到 `e:\ai_video_factory\assets\` 素材库目录，不得仅在 `outputs/` 中作为一次性产物。
- 每张素材附带独立 JSON 元数据文件，字段沿用现有素材元数据 Schema，并额外包含：
  - 标记为 AI 生成（与人工收集素材可区分）
  - 生成所用的完整提示词与负向约束
  - 生成的目标分镜 ID 与 pipeline ID（可追溯）
  - 生成时间与成本
- 文件命名遵循 constitution 第 5 条规范，AI 生成素材在命名中可识别。
- AI 素材可被后续视频复用——加入素材库后参与常规的标签检索。

### AC-6: 审阅与重新生成

- AI 生成素材作为分镜候选之一，进入既有**审阅点 2（分镜审阅）** 与**审阅点 3（成片审阅）**，不新增审阅点。
- 审阅界面必须区分素材来源（本地库 / 外部素材 / AI 生成），便于创作者重点检查 AI 生成内容。
- 审阅人可对 AI 生成素材执行三种操作：通过 / 打回（选其他候选）/ 重新生成（可附修改意见）。
- "重新生成"操作必须保留原分镜约束，仅在用户反馈基础上调整生成参数，不重新跑整条管线。

### AC-7: 配额与限流保护

- 单条视频 AI 生成素材数量有上限（默认 ≤ 8 张，可配置），超过上限时按分镜优先级排序生成，其余使用兜底方案。
- 必须支持生成失败重试与限流退避，连续失败 ≥ 3 次时自动暂停本管线内的后续 AI 调用，并通知用户。
- 必须支持"全局关闭 AI 生成"开关，关闭后管线行为与现状完全一致。

## 5. Non-Goals

| 不做 | 原因 |
|------|------|
| 文生视频（text-to-video） | 已在 `video-factory-optimize` Non-Goals 中明确排除，本规格仅覆盖静态图像 |
| 图生图 / 风格迁移 / 图像编辑（inpainting 等） | 本期聚焦"从无到有"的补位场景，编辑已有图像属于下一阶段 |
| 本地部署图像生成模型 | 违反 constitution 第 2 条"所有 AI 调用走云端 API" |
| AI 数字人 / 虚拟形象生成 | 与基础架构 Non-Goals 一致 |
| 替换现有素材库收集工作（T1.6） | AI 生成是"补位"而非"替代"，人工收集的高质量实拍素材仍为主线 |
| 生成视频中的文字内容（标题字、字幕字形） | 文字渲染由 Remotion/FFmpeg 负责，AI 生成图像默认排除文字 |
| 跨素材库的"风格统一管理后台" | 属于素材运营工具，不属于生产管线 |
| 用户上传参考图驱动生成（image prompt） | 涉及版权与素材来源风险，本期仅支持文字 prompt |

## 6. Constraints

### 技术约束

| 约束项 | 说明 |
|--------|------|
| 运行环境 | Windows 10/11，无 GPU（沿用现有约束） |
| 调用方式 | 云端 HTTP API，禁止引入本地推理模型 |
| 中文支持 | 必须支持中文 prompt 输入（原生支持或自动翻译） |
| 输出格式 | 配图/封面/背景：JPEG 或 PNG；透明元素：必须 PNG 带 Alpha 通道 |
| 与现有管线集成 | 必须复用现有素材检索模块的返回结构（`candidates` 数组），AI 生成结果作为候选之一注入，不破坏现有 `matchScene` 接口契约 |
| 审阅集成 | 必须复用现有审阅 API（`/api/review/:id/approve|reject`），不引入新的审阅通道 |
| 模板兼容 | 横竖屏两个 Remotion 模板必须都能消费 AI 生成素材，不需要为 AI 素材单独开发模板 |

### 资源约束

| 约束项 | 说明 |
|--------|------|
| 素材库根目录 | `e:\ai_video_factory\`（与 constitution 一致） |
| API 月预算 | 新增图像生成 API 费用 ≤ ¥30/月 |
| 磁盘占用 | AI 生成素材按 1MB/张估算，月均增长 ≤ 500MB |
| 命名与元数据规范 | 遵循 constitution 第 5 条三级层级与文件命名规范 |

### 合规约束

| 约束项 | 说明 |
|--------|------|
| API Key 管理 | 通过环境变量注入，禁止硬编码（constitution 第 7 条） |
| 内容合规 | 生成内容需通过图像 API 自带的内容安全过滤；项目侧不再单独做内容审核（人工审阅已覆盖） |
| 版权风险 | 默认排除真实人物肖像、知名 IP、注册商标 |
