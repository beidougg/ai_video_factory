## 1. Problem Statement

当前短视频内容生产面临三个核心痛点：

**生产效率瓶颈。** 从创意到成品视频，需要经过选题、写脚本、找素材、配音、剪辑、加字幕、各平台分别上传等多个步骤。即使是有经验的创作者，制作一条 60 秒短视频平均耗时 2-4 小时。批量生产时，这个时间成倍增长。

**质量一致性差。** 人工剪辑的每一条视频，在节奏、风格、画面质量上都有差异。当需要日更甚至多更时，一致性几乎无法保证。

**多平台分发重复劳动。** 同一视频发布到 YouTube、快手等平台，需要分别登录、分别上传、分别填写标题和标签。这些操作高度重复但无法省略。

**目标：** 用户只需提供一个创意点子，系统自动完成选题分析、脚本生成、素材匹配、配音合成、视频渲染、质检、多平台分发全流程。在四个关键节点暂停等待人工审阅确认。人工参与时间控制在每条视频 10 分钟以内。

## 2. Success Metrics

| 指标 | 目标值 | 测量方式 |
|------|--------|----------|
| 端到端生产时间 | ≤ 30 分钟（不含人工审阅等待） | n8n 执行日志时间戳差值 |
| 人工参与时间 | ≤ 10 分钟/条（四次审阅合计） | 审阅节点 Webhook 回调间隔 |
| 视频产出可用率 | ≥ 80%（无需人工二次修改即可发布） | 审阅"通过"率 |
| 视频质检通过率 | ≥ 95% | ffprobe 自动检测通过率 |
| 平台发布成功率 | ≥ 90%（YouTube + 快手） | 各平台 API 返回成功/失败计数 |
| API 月费用 | ≤ ¥100（含 LLM + TTS） | API 平台账单 |
| 素材库命中率 | ≥ 70%（AI 推荐的素材被采纳） | 审阅通过 vs 打回修改统计 |

## 3. User Stories

| # | 角色 | 场景 | 期望结果 |
|---|------|------|----------|
| US-1 | 内容创作者 | 我有一个视频创意，想快速生成一条成品视频 | 输入创意点子后，系统自动完成全流程，我在关键节点确认即可 |
| US-2 | 内容创作者 | 我想在生成过程中把控质量 | 系统在脚本、分镜、成片、发布信息四个节点暂停，推送审阅 |
| US-3 | 内容创作者 | 我的脚本被打回后，想让 AI 按反馈重写 | 我在审阅时写下修改意见，系统根据反馈重新生成 |
| US-4 | 内容创作者 | 我想替换某个分镜的素材 | 审阅分镜时可指定替换素材 |
| US-5 | 运营者 | 我想把视频发布到多个平台 | 审阅通过后系统自动发布到 YouTube 和快手 |
| US-6 | 运营者 | 我想知道发布后的数据表现 | 发布 24h 后自动回收各平台数据，飞书推送每日汇总 |
| US-7 | 内容创作者 | 我有一批高质量素材想沉淀复用 | 放入素材库并标注元数据后，系统在匹配阶段自动检索推荐 |

## 4. Acceptance Criteria

### AC-1: 创意输入与选题分析

- 用户通过 n8n Webhook 或飞书消息提交创意点子（纯文本，≤ 200 字）。
- 系统调用 LLM 分析选题方向、热点匹配度、受众适配性。
- 输出选题分析报告（≤ 300 字），含推荐角度和风险提示。

### AC-2: 脚本生成（审阅点 1）

- 系统根据选题分析 + 素材库目录结构生成完整脚本文案。
- 脚本 200-800 字，对应视频 30-120 秒。
- 每个段落附带画面建议。
- 完成后暂停，飞书推送审阅。
- 打回时可附带修改意见，系统根据意见重新生成。

### AC-3: 分镜与素材匹配（审阅点 2）

- 系统将脚本拆分为分镜列表，每个分镜从素材库检索匹配素材。
- 匹配基于标签、适用场景、质量等级三维度排序，每分镜推荐 ≥ 3 个候选。
- 无匹配素材时标记为"缺失"并提示补充。
- 分镜完成后暂停，飞书推送分镜对照表供审阅。

### AC-4: 配音生成

- 根据最终脚本调用 TTS 引擎生成配音音频。
- 默认 Edge-TTS（免费），可选切换豆包语音。
- 输出 MP3/WAV，采样率 ≥ 22050Hz。

### AC-5: 视频合成与渲染

- 系统根据分镜顺序 + 素材文件 + 配音生成 Remotion/HyperFrames 渲染代码。
- FFmpeg 执行最终合成：拼接素材、叠加配音、烧录字幕。
- 输出 MP4 (H.264)，1080p，渲染时间 ≤ 视频时长 × 3。

### AC-6: 自动质检（审阅点 3）

- ffprobe 检测分辨率、帧率、时长、编码格式、音频采样率。
- 质检失败自动重试（最多 2 次），仍失败则通知用户。
- 通过后暂停，飞书推送成片预览供观看。

### AC-7: 发布元数据生成（审阅点 4）

- 为每个目标平台生成标题、描述、话题标签。
- YouTube 标题 ≤ 100 字符，描述 ≤ 5000 字符，标签 5-15 个。
- 快手标题 ≤ 20 字，话题标签 3-5 个。
- 生成完成后暂停，飞书推送供审阅。

### AC-8: 多平台分发

- YouTube：通过 Data API v3 videos.insert 上传，默认 private。
- 快手：通过 openapi/photo 系列接口上传。
- 每个平台发布结果记录到 n8n 执行日志，失败自动重试 1 次。

### AC-9: 数据回收

- 发布 24h 后自动查询各平台视频表现数据。
- 回收数据：播放量、点赞数、评论数、分享数。
- 高完播率素材自动标记质量等级。
- 飞书推送每日数据汇总。

## 5. Non-Goals

| 不做 | 原因 |
|------|------|
| AI 文生视频（从文字直接生成视频画面） | 效果不稳定，成本高；素材库路线更可控 |
| 抖音 / B站 / 微信视频号自动发布 | 三个平台均无对普通开发者开放的发布 API |
| 实时视频直播 | 与短视频生产场景无关 |
| 多人协作编辑工作流 | 单人使用场景 |
| 移动端 App | PC + 飞书移动端审阅已满足 |
| 视频内容自动审核（鉴黄/鉴暴） | 人工审阅已覆盖 |
| 自动养号/账号矩阵管理 | 初期聚焦单账号 |
| 跨语言翻译与多语言配音 | 聚焦中文内容 |

## 6. Constraints

### 技术约束

| 约束项 | 说明 |
|--------|------|
| 运行环境 | Windows 10/11，无 GPU |
| 编排引擎 | n8n 自托管（Docker），版本 ≥ 1.0 |
| 主力 LLM | DeepSeek V3（兼容 OpenAI 接口） |
| 视频渲染 | Remotion（Node.js ≥ 18）+ FFmpeg（≥ 5.0） |
| TTS | Edge-TTS（默认），可选豆包语音 |
| 审阅通知 | 飞书应用机器人 |
| 内网穿透 | ngrok 或 Cloudflare Tunnel |

### 资源约束

| 约束项 | 说明 |
|--------|------|
| 素材库根目录 | `e:\ai_video_factory\` |
| 磁盘空间 | ≥ 50GB 可用 |
| 内存 | ≥ 8GB |
| API 月预算 | ≤ ¥100 |
